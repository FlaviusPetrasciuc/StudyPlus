# Coding Conventions

This project follows the standard basic Dart and Flutter coding conventions.

## Dart and Flutter Standards

We used the official Dart/Flutter style guidelines to keep the code clean, readable, and consistent.

## Naming Conventions

- Classes and widgets use `PascalCase`
    - Example: `CreateProjectScreen`, `ProjectCalendarScreen`
- Variables, methods, and functions use `camelCase`
    - Example: `projectName`, `generatePlan()`
- File names use `snake_case`
    - Example: `create_project_screen.dart`
- Constants use clear and descriptive names.

## Code Structure

- Code is divided into logical folders such as:
    - `screens`
    - `widgets`
    - `services`
    - `models`
- Reusable UI components are placed in the `widgets` folder.
- API and database logic is placed in service files.
- Data objects are stored in model classes.

## Formatting

- Code is formatted using Dart formatting.
- Proper indentation is used.
- Long code blocks are separated into smaller methods where possible.
- Unused imports and unused code are removed.

## Readability

- Variable and method names are descriptive.
- Widgets are split into smaller components when needed.
- The code is written in a way that other team members can understand and maintain.

## Comments

Comments are used only when necessary to explain important logic.

## Summary

Overall, the application follows basic standard Dart and Flutter coding conventions. The code is structured, readable, and uses consistent naming and formatting throughout the project.
